# Codefront 代码战场
产品与架构设计 / v0.1 / 2026-09-13

## 1. 产品目标与第一版范围
面向会写或正在学习 Python 的玩家。在同一个网页中编辑真实代码、观察机器人实时行动、邀请朋友进入同一战场。教学是可自由查阅的参考手册，不设课程解锁、强制引导或通关门槛。
第一版交付：真实 Python 与 JavaScript 执行；三台机器人采集与战斗；单人训练的运行、暂停、重置、速度调整；2–4 人真实云端房间；代码部署；机器人选择与行动观察；中文手册；GitHub 源码、测试、部署文档。画面优先保证流畅、可读、互动反馈明确。
第一版采用公开视野、单张四向对称地图、固定机器人属性、三分钟计时、能源交付计分。核心定时刷新，采集、护航与拦截构成策略差异。禁止把预录动画、硬编码采集路线或关键词识别冒充 Python 执行。
完整产品后续扩展：5–8 人、多张地图、团队模式、战争迷雾、持久回放、服务器 Python 沙箱、公平竞技。上述扩展不标为第一版已完成。
主要体验指标：打开页面即可看到战场与代码；无需阅读手册即可试运行；运行结果能随代码变化；多人分数与机器人状态由同一个云端规则引擎决定。

## 2. 对战规则与交互
每人控制 Scout、Guard、Hauler 各一台。Scout 速度快，Guard 血量和火力高，Hauler 运载量大。基地不可攻击。普通能源交付计 1 分，核心有更高价值。击毁机器人掉落其货物，机器人延迟重生。三分钟结束，以实际交付分数排名，同分并列。
动作包括 move、gather、attack、idle。move 前往坐标；gather 自动接近目标并采集；attack 接近目标并在射程和冷却允许时开火。进入基地范围自动卸货。每次每台机器人只有一个主动作；未指定动作延续原任务，idle 明确取消。消失目标导致等待，下一次决策可以选新目标。
页面左侧是编辑器，右侧是主要战场，下方显示事件和队伍状态。顶部提供训练、联机和手册入口。主要操作为运行策略、暂停训练、重置、部署新代码。代码草稿和正在运行的版本必须区分；保存草稿不会隐式部署。
训练默认搭配普通脚本对手。演示观察模式必须有明显标识，运行用户代码后显示实际语言和运行状态。训练支持暂停和速度调整；多人不能单方面暂停。错误信息保留原始异常，输出截断后提示，不伪造精确定位。
房间流程：创建房间并获得房间码；其他玩家输入房间码加入；房主在至少两人时开始；房间锁定席位；各客户端持续提交自己程序生成的动作；结束显示统一排名。浏览器刷新可以恢复席位。第一版不设排位，也不声称严格防作弊。

## 3. Sites 部署架构与取舍
宿主为 Sites Cloudflare Worker + D1。前端沿用 Sites Vinext/React/TypeScript starter，保留 sites() 构建插件；不引入需要常驻 Node TCP 服务的 Colyseus。战场使用 Canvas 2D 渲染动态游戏对象，避免为一张简单地图引入额外游戏引擎。
Python 在独立 Web Worker 中通过 Pyodide 执行真实解释器；JavaScript 在独立 Worker 中运行。每次接收 JSON observation 和 memory，返回 JSON actions 和 memory。Worker 超时后销毁，主线程保持响应。初始化时间与单次策略超时分开计算。
云端只接收动作请求，校验玩家归属、参数和比赛状态后推进权威模拟，并持久化到 D1。客户端不能提交血量、坐标、分数或其他玩家的动作。第一版以约 400 毫秒一次的 HTTP 请求交换快照，通过动画插值获得连续观感。快照频率与绘制帧率分离。
重要边界：客户端解释器可以被用户改造，因此不能证明收到的动作由提交的源代码生成。该版本用于朋友间休闲对战，不用于排位、奖金或严格公平比赛。严格竞技需独立 Linux 执行节点，使用 gVisor 等隔离执行 CPython；Sites 保留网页、房间入口及结果存储。
D1 不是高频实时服务器。第一版限制四人、三分钟、小型房间状态和有界事件记录，以乐观锁防止并发覆盖。压测后如冲突或写入延迟影响体验，替换为支持持久房间调度的独立游戏服务或经平台确认支持的 Durable Object。不能在未验证 Sites 绑定支持时假设可直接部署。
Python 资源采用 Pyodide 0.27.7，构建时从锁定依赖复制到本站静态目录；加载、失败与重试状态可见，不依赖第三方 CDN。浏览器本地运行不等同于服务器代码沙箱。

## 4. 数据协议、状态机和并发
入口：def decide(observation, memory): return actions, memory。observation 包含 tick、time、base、robots、enemies、resources、scores。机器人包含 id、owner、role、x、y、hp、maxHp、cargo、capacity、alive。资源包含 id、x、y、amount、value。坐标采用统一世界单位，左上角为原点。
actions 为 robot_id 到动作字典的映射。move 含 x/y；gather 和 attack 含 target_id；idle 无目标。只接受本玩家机器人；拒绝非有限数、未知动作和过大消息。memory 必须为可 JSON 序列化对象，设置大小上限。不要依赖解释器全局变量，第一版部署新代码时重置 memory，同一运行版本内保留通过校验的 memory。
房间状态：waiting → running → finished。只有房主可启动，至少两人，开始后不可加入新席位。所有写操作绑定随机席位凭证；数据库保存凭证摘要，API 不返回其他玩家凭证。请求包含房间码、席位令牌、动作序号。重复或过期动作不能覆盖新动作。
D1 rooms 表保存 code 主键、version、payload、updated_at；payload 包含席位与令牌摘要、世界快照、当前动作、最后服务端推进时间。乐观更新使用 UPDATE ... WHERE version = oldVersion；失败重新读取，限定重试次数并返回可恢复冲突。所有派生时间以服务端为准。
模拟采用固定 50 毫秒步长。每个请求最多推进有界数量步，到达三分钟墙钟截止后结束，创建一小时后房间过期，避免单请求无限追赶。移动、资源争抢、攻击和计分均由同一纯函数处理，训练复用该函数。读取接口过滤席位凭证和内部字段。
初版保留有界最近事件，不把它称作完整回放。后续回放记录权威动作、种子、规则版本、周期快照以及部署和错误事件；回放不重新执行不可信源代码。

## 5. 视觉、动画与可访问性
视觉方向：深海蓝战术桌面，青绿色友方、珊瑚红敌方、琥珀色核心，清晰的大面积战场。代码区像轻量工作台，操作按钮和比分高对比。图形是可交互的游戏对象，位置、尺寸、轨迹均反映真实游戏状态。
动画：机器人平滑移动并朝移动方向转向；采集时资源产生短脉冲；攻击用短暂弹道和命中闪光；交付弹出加分数字；重生扩散光环；核心呼吸效果与出现提示。所有效果由真实模拟状态或事件触发，不虚构击中或得分。
鼠标点击机器人显示血量、载量、目标、坐标；可切换路径与射程辅助显示。暂停时停止模拟，装饰动效遵守减少动态效果偏好。Canvas 配套文字比分、队伍列表、事件日志和说明，关键操作使用原生可键盘访问按钮。
桌面采用双栏；窄屏转为战场优先纵向排列，编辑器保留可用高度。主要文字至少 16px，按钮和常用标签至少 14px。检查 1366、1440、1920 宽度以及手机窄屏；不能横向裁掉部署、房间码和错误提示。
绘制目标为常见桌面设备接近 60fps；这是一项验收目标而非已测性能。限制粒子总量，按设备像素比缩放 Canvas，后台页暂停绘制；离开训练或切换模式时释放 Worker 和计时器。

## 6. 发布、风险与扩展决策
GitHub origin 固定为 https://github.com/hjkc111/codinggame.git。Sites 源仓库作为独立发布 remote，两个 remote 推送相同提交。不得把 Sites Git 端点误作网站地址。Sites project_id 保存在 .openai/hosting.json，后续维护复用同一 Site。
先通过构建、规则测试、三个真实浏览器上下文联机、Python 行为与异常验证，再发布 Worker + D1 完整包。检查最终部署状态和线上完整流程，不能只验证首页 200。GitHub Actions 运行安装、测试、构建；Sites 发布仍由发布工具完成，不宣称 GitHub push 自动部署。
用户已于 2026-09-13 明确授权公开链接，最终访问范围设为 public，任何拿到网址的人可进入。房间仍使用独立席位令牌鉴权。后续变更访问范围应遵循用户指定范围。
数据最小化：昵称、随机席位标识、比赛状态。草稿仅存当前设备并标注；联机状态存云端。不得把令牌写进 Git、文档或公开日志。第一版不收集邮箱、不设聊天和用户上传文件。
后续优先顺序：服务器解释器与房间调度；完整回放；5–8 人与团队模式；地图与迷雾；C++ 编译执行。进入下一阶段的条件是现有训练和多人闭环可靠，不能以新功能掩盖同步和执行问题。
参考：Sites 插件项目与托管能力文档；https://pyodide.org/en/stable/usage/webworker.html；https://gvisor.dev/docs/architecture_guide/security/。具体依赖版本以 package-lock.json 和 Python Worker 的固定发行版本为准。
