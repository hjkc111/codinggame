# Codefront 多轮赛制与优化计划
版本：v0.2 ｜ 2026-09-13
本文件是本轮开发与验收依据。01、02 为首版历史设计；发生冲突时以本文件与网站手册为准。开发状态与发布证据见 03。

## 一、完整玩法与节奏
2–4 位玩家进入同一房间，每人用 Python 或 JavaScript 控制三台机器人。采集能源、运回基地得分，也可以攻击敌方运输队；核心每枚价值 20 能量。单轮战斗 180 秒。
双人采用最多三局、先赢两局获胜。单轮交付相同算平局，不计胜场；三局后按胜场比较，仍相同则整场平局。不会无限加赛。
三至四人固定三轮积分赛。四人按名次得 4、3、2、1 分，三人得 3、2、1 分。同分并列占据相应名次，平分这些名次积分，例如四人第一并列各 3.5 分。总积分相同再比较累计交付，仍相同则并列冠军。
首轮准备不限时，房主可开启十分钟提醒。每轮后默认五分钟调整提醒；时间到不强制开始。只有所有玩家验证代码并准备后，才进入三秒倒计时。可以取消准备继续修改。教程随时查看，无强制关卡。

## 二、公平性与保留规则
每轮轮换出生位置，玩家 ID、颜色和机器人 ID 保持不变。双人交换两侧，三人轮遍三处，四人三轮各访问三个位置，尽量减少位置优势但不承诺完全消除。
局间保留编辑草稿和成功部署的程序；重开整场也保留代码。每轮清空显式 memory、动作和当轮分数。请使用 memory 保存决策状态，不依赖 Python 全局变量跨轮初始化。
局间展示每人采集能量、交付能量、死亡次数、当轮积分和累计积分/胜场。采集多而交付少可检查返航与运输损失；死亡多可调整攻击距离和撤退阈值。未交付载货不计分。
核心占一个货舱格，价值 20 能量。cargo 是携带能量，cargoSlots 是已占格数，capacity 是货舱格数。移动负载使用格数计算，避免核心显示成超载及异常减速。
进入房间后先运行或验证程序，再点准备；修改草稿会取消准备。战斗中仍可部署修改，失败保留旧版本。离线客户端不会继续执行 Python；服务端延续最后动作。

## 三、开发架构与协议
沿用 React/Vinext、Canvas、Worker 中 Pyodide、Cloudflare Worker 与 D1。保留公开 Sites 网站和 GitHub 仓库绑定，不新增托管服务或运行依赖。
lib/game.ts：纯战斗逻辑、出生轮换、采集/交付/死亡统计和货舱格数。
lib/series.ts：纯房间状态机、准备、倒计时、局间、积分和重开整场。时间显式传入，方便测试，不在公开接口增加快进后门。
app/api/rooms/route.ts：验证席位凭证、调用状态机、使用 D1 version 乐观锁一次提交。轮次结算与状态推进同一事务更新，冲突重读后计算，避免重复计分。
每个动作和准备请求携带 match 与 round，拒绝上一轮/上一场的延迟指令。响应附 revision，客户端忽略旧快照；异步解释器决策也校验轮次。令牌仅存哈希于 D1，公开响应不泄漏令牌。
JSON 房间格式升级到 2；旧格式房间提示新建，不静默改变正在使用的旧协议。无需修改数据库表或破坏已有迁移。

## 四、界面与交互优化
房间顶部展示赛制、当前轮次、全员准备状态、准备提醒倒计时和操作。战场保留实时动画、视角提示、轨迹与事件效果；不把局间复盘遮罩铺满代码编辑器。
复盘卡展示本轮统计与历史轮次，明确最终冠军/平局。局间可以直接编辑、部署、查看手册，再准备下一轮。房主可以延长提醒或结束计时；整场结束可原房间再赛。
网络同步维持约 400 毫秒，绘制插值保持画面平滑；这不是 WebSocket，也不承诺毫秒级对战。使用服务器时间显示阶段提醒，服务端控制结算。
移动端支持阅读、编辑和查看战场；复盘表可横向滚动，页面本身不应横向溢出。主目标仍是桌面编程体验。

## 五、实施顺序与验收
第一步：先完成本设计；第二步：实现战斗统计及房间状态机；第三步：接入全员准备、多轮复盘、代码保留；第四步：更新手册与开发状态；第五步：测试和发布。
单元测试覆盖双人提前结束、三轮上限、平局、多人并列积分、出生轮换、重复结算、旧轮动作、准备超时不强开、倒计时取消及整场重开。
战斗测试覆盖普通采集、核心格数、自动交付、死亡掉落和确定性。类型检查与生产构建必须通过。
浏览器测试验证真实 Python 执行、修改部署、错误恢复、多人准备与同步、局间统计及跨轮策略延续、移动布局。完整赛程使用真实 180 秒轮长；测试报告注明实际覆盖范围。
发布前推送 GitHub 和 Sites 对应源码，读取完整提交 SHA，打包生产构建并发布原公开网站。发布后检查线上 Python 与多人接口，不把 HTTP 200 等同功能验收。

## 六、范围与后续目标
本轮不增加排位、账号、战争迷雾、Agent、强制教程或复杂装备。优先保证一场朋友对战能够自然完成多轮，并能根据战况改进代码。
第一版执行仍在玩家浏览器，适用于朋友间休闲对战，不具备服务端可信代码执行和反作弊保障。断线重连恢复席位，但刷新后需要重新验证运行程序。
未来可根据试玩反馈增加离线席位处理、完整回放、地图镜像与积分平衡；这些不计入本轮已实现内容。四人三轮位置不能完全均衡，后续可提供四轮自定义赛。
