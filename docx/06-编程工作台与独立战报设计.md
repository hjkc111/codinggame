# Codefront 编程工作台与独立战报设计
版本：v0.4 ｜ 2026-09-13
本文件取代前版关于左右分栏编辑、实时热修复联机与高频快照观看的设计；保留双人三局两胜、三至四人三轮积分及轮换出生点。

## 一 问题与交互调整
旧编辑器只占屏幕约三分之一，长代码需要横向滚动。语法高亮层与透明输入层分别排版，中文、字体回退和换行容易造成光标错位。本轮使用单一可见文本输入层，浏览器原生显示光标与选区；默认自动折行，整页宽度用于编程，提供真实逻辑行/列位置与字号调整。
战场放入可手动打开、关闭的宽幅弹窗。训练运行及战报完成后可以自动打开，关闭不丢代码和播放位置。弹窗支持暂停、0.25/0.5/1/2/4 倍速、进度拖动和重新播放，所有播放控制只影响本机观看。
页面顶部固定提供带边框的只读 API 说明和 SDK 源码：机器人字段、世界对象、动作函数、坐标单位、空值和 memory 的意义均使用中文注释。显示“系统提供，只读；不要复制到策略里修改”。用户代码仍在下方独立编辑，不要求先过教程。
三台机器人分别编写 scout、guard、hauler 函数。每台拥有独立 memory，可以设置资源目标、追击对象、返航条件、巡逻路线和逐点移动。Python 通过 robot.x、world.resources 和 robot.move_to 等接口减少字符串字段拼写；保留旧 decide(observation, memory) 接口，旧草稿不自动覆盖。

## 二 计算与播放架构
玩家准备时提交本轮代码和语言；全员准备后代码锁定，进入计算阶段。代码提交会在界面说明本轮源码对房间成员可见，请勿包含密钥。成员离线不再影响已经生成的战报。
一位协调玩家的浏览器使用独立 Worker 执行每位玩家程序，按固定 0.2 秒模拟时间采样决策；战斗内部固定 0.05 秒推进，单轮 180 秒。计算速度取决于设备、解释器和网络，无需等真实三分钟。
协调端分批上报动作，服务端用相同战斗规则校验动作并推进权威世界，忽略客户端分数和血量。D1 原子保存房间进度与规范化动作批次；重复批次不重复推进，旧计算批次不能混入新轮。浏览器协调仍适用于休闲对战，不能证明动作必然来自已提交代码，不宣称严格反作弊。
计算完成后，每位玩家下载同一份初始状态和动作日志，在本机播放。采用确定步长与检查点支持快进和拖动；播放时不重新执行玩家代码，不按墙钟重新决定胜负。随机数或时间相关程序只计算一次并记录动作，所以各客户端也会看到相同结果。
网络只负责房间操作、提交、批次计算和战报下载；不再持续传输战斗画面。Canvas 使用 requestAnimationFrame 绘制，目标是设备允许的 30/60 帧或更高刷新率；逻辑步长和绘制帧率独立，不承诺所有设备恒定 60fps。

## 三 错误兼容与多轮流程
提交前验证程序入口和一次决策。计算中出错或超时，该玩家后续动作置为空闲，并记录玩家名及错误供复盘，其他玩家继续。Worker 的隔离和超时不等于可信服务器沙箱。
计算协调页面关闭或失联后，超时恢复准备阶段并使旧计算批次失效，可以重新准备计算。阶段变化使用 match、round 和计算编号隔离；旧协议房间提示重新创建。
计算结束便生成当轮正式成绩；每人可以按自己的速度观看，下一轮仍要所有玩家再次准备。代码草稿跨轮保留；memory 在新轮清空。整场结束支持原房间再赛。
原实时战斗中热部署调整为“修改下一次提交”；已生成战报不可改变。训练也按提交策略生成可调速战报，编辑修改后重新运行即可对比。本轮不会悄悄把暂停或加速变成影响他人的联机控制。

## 四 实施与验收
实现顺序：只读 SDK 与独立角色模板；全宽原生编辑器及战场弹窗；确定性动作日志和本地播放器；多人提交、批次计算与 D1 持久化；更新手册和测试后发布原站点。
单元验收：路径逐点循环、分角色分配与独立记忆；动作校验；批次重复和乱序、跨轮隔离、计算失联；回放从头与任意检查点得到相同状态；暂停和改变播放速度不改变最终分数；保留多轮和平局规则。
真实浏览器验收：Python 与 JavaScript 都能运行；光标与文本同层、长行自动折行、Tab 缩进、字号变化与中文输入；手动开关弹窗、所有倍速和进度拖动；三名独立玩家提交后计算完成，各自不同速度播放且最终成绩相同，刷新仍能下载已完成战报；手机布局无页面横向溢出。
产物保存在 docx 文件夹，包含 Markdown 原稿和 DOCX。数据库使用新增迁移，不覆盖既有表迁移。发布后验证普通公开网址实际运行新版，不把平台成功状态等同于完整验收。
