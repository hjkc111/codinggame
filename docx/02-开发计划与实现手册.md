# Codefront 开发计划与实现手册
版本 v0.1 / 2026-09-13

## 1. 开发阶段与验收
M0 设计与关联：生成完整设计、实现手册、状态文档；连接 GitHub origin；注册一次 Sites 并保存关联。验收：文档可打开且布局正常，仓库关联可查询。产品实现须在设计文档写成之后开始。
M1 规则核心：实现世界初始化、三角色、资源、采集、攻击、死亡、重生和比赛结束。以纯模块同时服务训练与云端。验收：同样状态与动作得到同样结果；越权和非法动作无效；得分只由交付产生。
M2 真实执行与视觉：Python/JS Worker、编辑器、超时处理、错误面板、Canvas 动画、运行/暂停/重置、选中机器人、速度调整。验收：改变 Python 阈值后可观测到不同行为；死循环后页面仍响应；暂停后世界时间不变。
M3 联机：D1 schema 与迁移、房间创建/加入/启动/轮询/动作提交、凭证、并发版本校验、刷新恢复。验收：三个独立浏览器上下文完成比赛；同一 tick 分数一致；非房主不能启动；开始后拒绝新席位。
M4 教学与发布：完成自选手册、真实示例、README、CI、构建、GitHub 推送、Sites 发布、线上验收、状态文档更新。验收：首次用户无需教学通关即可运行；线上 Python 实际执行；线上多人数据一致；部署状态成功。
M5 后续阶段：服务器 Python 隔离执行、专门房间调度、8 人和团队赛、完整持久回放、迷雾与地图。不能将 M5 文档中的计划项计入 M4 完成率。

## 2. 模块实现与维护入口
app/page.tsx：产品入口与客户端工作台。管理训练、房间、编辑草稿、运行状态、手册；网络错误需要可见。避免将游戏规则散落到 React 回调中。
app/globals.css：全站视觉 token、工作台布局、按钮、面板、弹窗和窄屏适配。装饰不能覆盖编辑器、遮挡错误或阻止点击。
lib/game.ts：类型、创建世界、动作校验、step、固定对手、observation。该模块不能读 DOM、网络或系统时钟；当前时间由调用方传入。事件数量有界。
components/Arena.tsx：Canvas 绘制、坐标换算、插值、选中机器人和动画。绘制不改变权威世界。世界尺寸统一，鼠标坐标按 Canvas 实际矩形转换。
public/python-worker.js 与 public/js-worker.js：执行入口、stdout 截断、结果序列化、错误返回。主线程执行代理负责超时终止、任务 ID、加载失败与恢复，不能在 React 主线程直接 eval 用户代码。
app/api/rooms/route.ts：创建、加入、启动与同步。所有数据经验证后交给规则核心。db/schema.ts 管理 D1 表，drizzle/ 保存生成迁移。版本锁冲突必须安全重试，不允许覆盖别人的最新动作。
tests/：规则回归与 API/浏览器验收；scripts/：可重复文档生成、浏览器验证等开发工具。docx/ 保存可编辑 Markdown 原稿及正式 DOCX；QA 图片和本地临时产物放忽略目录。

## 3. 本地运行、测试与发布
环境：Node.js 满足 package.json engines；使用仓库锁文件 npm ci。Windows 若 npm.cmd 包装器异常，可使用 node 指向本机 npm-cli.js，不能据此修改产品逻辑。
先运行 npm run db:generate 生成迁移，再运行 npm run build。按照 README 的 Wrangler 命令将尚未应用的 SQL 应用到本地 D1；不要重复运行已应用迁移。npm run dev 启动开发网页；npm start 验证构建产物。
测试顺序：npm test → npm run build → Python Worker 浏览器实测 → 三客户端真实 API 联机 → 响应式与截图检查。新增变更只重测受影响部分，失败和未验证项写进状态文档。
发布顺序：确认 .openai/hosting.json 同一 project_id；提交源代码和文档；推送 GitHub origin 和 Sites 源 remote；读取完整 HEAD；Sites package-site.mjs 打包；保存版本并部署；等待终态；线上检查。凭证只在单次 Git 调用内使用，不落盘。
回滚：从 Sites 已验证的历史版本重新部署。数据库迁移可能已在失败发布中应用，因此只追加兼容迁移，不通过覆盖旧 SQL 回滚数据库。源码回滚使用新提交保留历史，不强推覆盖远程历史。
CI：每次 push/pull request 运行锁定安装、规则测试和构建；浏览器重型验收可本地或专门任务执行。CI 通过不代表线上运行正常，状态文档分别列出本地、CI 和部署验证。

## 4. 玩家操作手册与教学内容
训练：打开网页即可看见战场；编辑 Python；点击运行策略；首次解释器加载时等待明确的状态提示；观察采集与交付；点击机器人查看状态；暂停、修改并部署；重置开始新局。切换语言会替换示例前应保留原草稿。
联机：创建房间，复制房间码；朋友打开同一网址并获得站点访问权限后输入房间码；至少两人后房主开始；每个人运行自己的程序。多人页面不能暂停整局。客户端暂时离线时云端使用最后一个有效动作；恢复后继续提交。没有后台常驻解释器，不承诺断线后 Python 继续决策。
入口解释：decide 每隔一段时间接收战况，返回动作和记忆。普通局部变量只属于本次调用；跨次信息写进 memory。resources/enemies 可能为空，先判断再 min。目标可能在下一刻消失，策略要能重选。
渐进示例：最近资源采集；满载返航；血量低返航；按角色分工；根据比分抢中心核心。每节提供字段解释、可运行代码、预期行为与可选实验，不记录强制通过状态。
常见错误：缩进错误检查空格；KeyError 对照字段文档；返回格式错误检查 actions, memory；机器人不动查看当前动作、目标和错误；加载失败检查网络并重试；超时避免无限循环和巨大穷举；修改没生效查看草稿与运行版本。
测试与教学一致：示例必须在真实浏览器 Python 解释器中执行并产生有效动作。演示脚本不能替代用户代码运行；截图仅证明视觉，不能证明解释器或多人流程。
