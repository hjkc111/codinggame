规则测试：5 项通过。包括动作所有权和有限坐标、资源必须交付、死机不采集、确定性完整比赛、同时击毁、观察数据归属；事件列表数量有界。
类型与构建：TypeScript 无错误；Vinext 五阶段构建完成，生成 Worker、静态资源、D1 迁移。构建 Worker 在本地端口 8787 单独验证，不仅测试开发服务器。
浏览器：Chrome 独立上下文验证 Python 实际运行；修改程序后机器人转为前往中心；暂停后计时不变；死循环触发超时但页面可操作且旧版本继续；手册自由打开关闭；390px 手机宽度没有横向溢出；无浏览器 pageerror。
多人：三位玩家从真实房间界面创建、加入并开始完整 180 秒比赛，使用 Python / JavaScript / Python。中途刷新第三位玩家，恢复席位并重新运行 Python；所有客户端最终比分完全一致。另测非房主启动返回 403、开始后加入返回 409，真实 API 三客户端同步通过。
证据位置：可复用脚本 scripts/browser-check.cjs、tests/game.test.ts；本地证据 .qa/browser-results.json、.qa/full-match-results.json 与桌面、手机、手册、联机截图。QA 目录不进入 Git，避免携带临时会话。文档使用 Word 导出 PDF 再逐页检查；当前环境无可用的 bundled LibreOffice。

## 限制与后续目标
未完成且未宣称：服务器 Python 沙箱、严格防作弊、排名、5–8 人、团队模式、障碍地图、战争迷雾、完整持久回放、服务器常驻决策、房间过期自动清理。当前是公开链接的休闲首版。
并发容量与稳定 60fps 尚未做生产压测，不提供性能保证。HTTP 请求频率并不等于网络实时延迟；线上延迟需独立测量。公开页面的 Python 在用户设备执行，不能证明动作来自提交的代码。
后续优先级：线上反馈与同步性能；专用房间调度和服务器 Python 隔离执行；持久回放；团队与八人；地图和迷雾。维护时同步更新 Markdown 原稿与 DOCX，不覆盖旧迁移，不改变 Sites 关联。
